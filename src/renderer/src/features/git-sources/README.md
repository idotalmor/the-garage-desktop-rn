# Desktop Git sources

| File                    | Purpose                                                                                                                    |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `GitSourcesPanel.tsx`   | Gravity UI connect/device-code controls, account refresh/disconnect, paginated favorites picker                            |
| `open-url.ts`           | `openGitHubUrl(url)`: dispatch browser opening to main over `OpenUrl` IPC; static warning on failure                       |
| `useGitSources.ts`      | Initial snapshot, changed subscription, device polling trigger and action/error state                                      |
| `repositories.ts`       | Pure `repoIdentity` and `mergeRepos`: local clones plus favorites, not the full catalog                                    |
| `useGitRepositories.ts` | Compose snapshots and preserve desktop ordering in localStorage while saving local clone positions through existing action |

Flow: `DashboardHome → useGitSources → IPC`; `local snapshot + Git sources snapshot → useGitRepositories → repositories.mergeRepos → shared GitHubCard UI for both local checkouts and remote-only favorites (same sizing, branch header, surface and footer layout)`. All cards are composed by `github/components/repository-cards.tsx`; the dashboard has no separate remote-card markup. `GitHubLink` is shared by the card's top-right action and the repo heading (between its color dot and name), and renders nothing without a URL. `repositories.ts` exposes `githubUrl` from cached provider metadata or a known normalized GitHub primary remote, so local repo links do not require a connected account. Remote-only favorites have no text-link footer, local history/action buttons or invented PR/CI data. Existing local IDs and worktree paths remain unchanged. Only primary remote slugs match; a fork's upstream never steals the fork's card. Two separate clones retain two sets of local actions. Case-normalized host/fullName matches SSH and HTTPS through the existing scanner slug parser.

GitHub web links use `openGitHubUrl → OpenUrl IPC → main shell.openExternal`, including repo header/card links, PR buttons and the authorization-page button. Repo anchors prevent default navigation (including middle-click) so they cannot create Electron popups. The initiating Connect action already opens its verified authorization URL in main and is unchanged. Restart Electron after installing the new handler; renderer-only hot reload is insufficient. Window creation/global popup policies are not changed.

The settings control uses a 14px `Gear` from `@gravity-ui/icons` in the same 28px HeroUI ghost button styling as the neighboring source actions: centered, muted, rounded and transparent until hover. It has no separate Gravity theme wrapper or custom background/size tokens; Gravity remains scoped to the settings panel itself. The settings icon beside the dashboard's Git heading toggles the connection/favorites/clone-from-URL panel independently of repo-card collapse. Settings start hidden; new connection errors or device authorization instructions automatically reveal them. The panel stays mounted while hidden so pasted URLs, branch input and favorites-picker state survive toggling, and in-flight operations continue. The button exposes `aria-expanded`, `aria-controls`, and an action-specific accessible label; the hidden panel is removed from keyboard navigation.

The picker loads 100 repos per page only when opened. Filtering applies to loaded pages, clearly labeled. Failures retain cached cards; stale picker responses are ignored when closing/switching. Disconnect asks for confirmation and only removes device-local connection data. Scoped Gravity ThemeProvider follows the app theme and uses semantic `--g-*` tokens; existing HeroUI components are not migrated.

Checkout flow: `DashboardHome.startCheckout → useGitSources.createCheckout → PrepareCheckout IPC → native parent-folder picker → CreateCheckout IPC → clone/worktree → local source scan → mergeRepos`. The card-spec builder injects `CloneAction` only when a branch has no usable local checkout (remote-only favorites, default branches without checkouts and unlinked non-detached worktree cards). A linked default-branch checkout is reused rather than rendering a second clone button. The initiating repo shows progress, duplicate checkout clicks are disabled, canceled pickers do not write, and errors are displayed in the connection panel. New clones authenticate in main; credentials never reach the hook. Local-only branches need no provider connection.

**Clone from URL** accepts a pasted GitHub HTTPS or SSH repo root plus an optional branch. It uses the same checkout plan/native parent picker/creation flow, not a second cloning implementation. Known clones suggest sibling parents; existing checkouts of the requested branch are reused. New clones register as scan sources and appear as local cards without needing a favorite or account connection. Completion reports the actual checkout path; errors preserve the input for correction and canceled pickers produce no success message. GitHub SSH uses configured SSH authentication; HTTPS uses a matching cached account, the sole connected account for an uncached repo, or Git's credential setup.

Desktop membership is machine-local. No Firestore changes, provider stars, PR or CI fetches are included. Ordering is a UI preference under `the-garage.git-sources.order`; local order is still saved through `local-repos`.
